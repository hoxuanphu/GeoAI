# Task 4 — job core before database/native integration

Read plan.md, implementation-gaps.md, SPEC-004, ipc-protocol.md state/race/checkpoint sections, ADR-002/009/011, contracts.py/runs.py and Task2/3 reports for existing APIs. Do not repeat completed prior foundation. TDD, no subagents/Git/global installs. Parent owns docs/spec/roadmap/tracker.

Implement jobs/coordinator.py or narrowly named job core with immutable internal snapshots and explicit application service/repository boundary. This task operates metadata only in memory/functional transitions and does not open DB or start compute. No new API route/capability. SQLAlchemy/Alembic remain required for eventual repository: verified retry in new isolated .venv-backend failed downloading SQLAlchemy wheel HTTP403, so do not silently use sqlite3 as substitute or call in-memory conditionals durable fencing.

Required semantics:

- Enqueue validated JobSpec canonical full-payload JSON bytes (UTC/model dump, sorted keys, no nonfinite) and versioned SHA256 digest; idempotency scoped project+key. Same key/same canonical payload returns same job; different payload conflicts. Reject duplicate job ID with conflicting key/payload; never overwrite prior intent. Explain exact digest profile; no external approved business values.
- Snapshot input intent in bytes so nested mutable parameters cannot mutate stored request/digest. Return defensive views/snapshots; caller cannot alter active token/state through a returned dict/Pydantic nested object.
- queued/running/cancel_requested/succeeded/failed/cancelled transitions from IPC, terminal attempt never returns live. Allocate fresh AttemptKey/generation token internally (caller/UI does not choose it); bounded retry config must be explicit, no unlimited default. Retry creates new attempt/token, stale events/candidates/token do not change new state. Generation token is not request/idempotency ID.
- Cancel queued can finish without worker; running cancel blocks publication immediately but does not pretend worker stopped. Cancel ack is not stopped. Confirmed stop is a separate trusted-coordinator observation recorded via explicit method before cancelled or retry/new attempt; unconfirmed crash/timeout/heartbeat does not permit reassignment. This class cannot verify OS processes; metadata confirmation is NOT native evidence and must not be exposed to untrusted client. Keep this distinction obvious in code/docstrings/tests.
- Publish authorization requires full current key and running state, not succeeded/cancel_requested/stale. Apply publication metadata once only through a documented trusted validated-publication boundary, after external bytes/grid/coverage/manifest checks which are NOT implemented by the core. Unique publication/job and cancel-before-publication versus publication-before-late-cancel deterministic state semantics. No filesystem rename, hashing file bytes or DB commit claims.
- Failure/retry/cleanup/resume: revoke old metadata authorization before next attempt, explicit retry bound, cancelled does not auto retry, succeeded late cancel leaves success. Checkpoint compatibility helper locks input/model/config/runtime/grid identity; mismatch rejected. Define new serialized checkpoint identity in Pydantic only if needed, fixture/exporter/docs/test together. Does not claim native checkpoint usability, dependency pin/lease, GC or DB recovery.
- Reuse Task2 grant/candidate scope and Task3 wire types where it helps real composition; do not force circular imports/storage->jobs. jobs may import storage, never workflows. If no native actor available, keep real core test composition with trusted metadata registry and synthetic validated candidate. Avoid fake heavy worker/framework scaffolds.

Tests: same/different project idempotency, payload hash canonicalization and mutation, all legal and forbidden transitions, cancel queued/running/ack/stop, late cancel, stale progress/candidate after retry, token rotation, bounded retries, failure stop unknown, publication uniqueness/race ordering, checkpoint each identity mismatch. No mock-only assertions or claims process/SQLite tests. Optional deterministic threading test may test metadata lock but must NOT be called DB fencing. Expose narrow API and document requirements for transaction adapter/native owner later.

Run jobs/contracts/storage/architecture plus existing integration/artifact checks if new schemas. No UI changes. Report task-4-report.md with internal API, integration example, exact RED/GREEN logs/commands/counts, covered state semantics and remaining owner/DB/publisher/native/G0 limits.

# Task 7 native owner, containment, Tauri handoff - 09/11/2026

## Delivered source

- `backend/geoai/storage/windows_owner.py`: production `ExecutionOwner.acquire()` has one fixed account-wide `v1` namespace under OS-resolved LocalAppData/SID. Private directories, lock files and records use an explicit protected current-SID DACL. Owner and project writer use non-inheritable exclusive Win32 file handles. Owner metadata includes positive epoch, owner ID, PID, process creation time, session ID and registered group names. Project writer checks the held root's volume/file ID and implements `WriterGuard`/`GuardLease` structurally. Both close paths refuse live leases/groups. Unclean records compare PID plus creation time and query named Job Objects; absent, unknown or active groups block recovery.
- `backend/geoai/jobs/native_process.py`: `ManagedProcess` creates kill-on-close Job Object, anonymous stdio pipes and `STARTUPINFOEX` with both `PROC_THREAD_ATTRIBUTE_HANDLE_LIST` and `PROC_THREAD_ATTRIBUTE_JOB_LIST`. `CreateProcessW` is the first process creation operation; there is no spawn-then-assign path. Parent ends are non-inheritable. Executable must be absolute; environment is an explicit OS-variable allowlist plus two designated runtime fields. Group state comes from Job Object accounting. A bounded stderr drain discards raw diagnostics. Owner intent is recorded before process creation and cleared only after confirmed group stop.
- `backend/geoai/bootstrap.py`: native private-pipe mode acquires the execution owner, requires current Job Object kill-on-close, and uses production Origins only. Existing two-flag dev mode remains. API capabilities remain false.
- `apps/desktop/src-tauri/src/{main.rs,windows_native.rs}`: source for one serialized sidecar session, main-window/current-URL authorization and navigation restriction, exact descriptor validation, trusted bundled runtime or compile-time debug runtime, atomic Windows job/handle-list creation, bounded descriptor read, continuous stdout/stderr drain after the descriptor, graceful shutdown then bounded group stop, and Job Object handle lifetime tied to shell. Tauri creates only the trusted main webview. No Cargo.lock was invented.

## Task 8 handoff

`ExecutionOwner.acquire()` returns the lifetime owner; `owner.acquire_writer(project_id, trusted_absolute_project_root)` returns a structural `WriterGuard` with read-only `owner_id`, positive `owner_epoch`, `assert_held(project_id)`, `retain(project_id)` and `close()`. A retained lease has `assert_held(project_id)` and idempotent `close()`. Owner must outlive writer, repository leases and managed groups. `owner.close()` refuses while any of those are registered. `_acquire_for_test(test_namespace)` is only for isolated tests.

After a verified prior generation and a live current writer exist, `owner.recovery_evidence(writer_guard)` returns an internal `OwnerStopEvidence` with `assert_stopped(project_id, old_owner_id, old_owner_epoch)`. It accepts only the exact immediately prior generation recorded during acquire and rechecks the same held writer/project every call. It refuses no prior proof, mismatched/current/future epoch, wrong owner/project or a closed writer. A missing named Job Object is not stop proof and blocks owner acquisition, so it cannot produce evidence for repository lease reconciliation.

`ManagedProcess.launch(executable: Path, argv: Sequence[str], environment: dict | None = None, child_handles: Sequence[int] = (), job=None, owner: ExecutionOwner | None = None)` returns a process with owned binary `stdin`, `stdout`, `stderr` streams, `pid`, `name`, `wait(seconds) -> bool`, `group_stopped(seconds) -> bool`, `terminate_group(seconds=5) -> bool`, `close()`, and optional `start_stderr_drain(max_count=65536)`. `job` must remain `None`; external Job Objects are deliberately refused until a verified trusted wrapper exists. `child_handles` are extra explicitly inherited handles; the caller must create/own them and close its child ends after launch. Task 8 owns framing, stdout reader, heartbeat and worker protocol; it must drain stderr or call `start_stderr_drain` immediately. Do not release owner before `ManagedProcess.close()` has confirmed zero active group processes. Native process failures raise sanitized `NativeProcessError`; ownership failures raise `OwnershipError`.

## Pending acceptance and limits

- Rust/Tauri source is unbuilt. Its exact API bindings, WebView2 behavior, bundled sidecar resource and debug compile-time runtime paths still require Cargo/MSVC/Tauri CLI and an actual Windows webview run. No bundled interpreter or model was created. Native session descriptor, startup timeout, close and shell-crash behavior have not been exercised through Rust.
- Cross-session same-account contention, alternate install paths, nested Job Objects under the final shell/worker hierarchy, process creation on unsupported Windows versions, clean bundle and installer remain unverified. This host's same-session ctypes tests cannot prove them.
- Owner recovery is intentionally conservative: malformed/missing group proof or denied Job Object query returns `recovery_required`; no PID from durable text is killed. After a crash that destroys the last named Job Object handle, this implementation cannot automatically prove group stop, so the next owner remains blocked pending an explicit supported recovery path. This is not a general automatic repair for corrupted records.
- Final native/dev shell check after evidence and sentinel fixes: [log](task-7-owner-evidence-tests.log), **25 tests OK**, command exit 0. New tests cover exact old generation evidence, live writer binding, missing named job refusal and an object-identity handle sentinel; the sentinel case passed 20 consecutive runs after replacing a numeric-handle assertion that could collide with an unrelated child handle.
- Project root identity checks guard writer selection, while Task 9 native resolver owns path-confined file I/O. The API still exposes metadata routes only; writer/job/API integration and G1 acceptance are pending. No capability flag is promoted by these tests.

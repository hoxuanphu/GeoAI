## Delivered

- `WorkerTransport.launch(executable, packet, owner=None, bootstrap_timeout=10)` uses `ManagedProcess.launch` with one explicitly inherited bootstrap handle. It checks owner ID/epoch when supplied, writes one bounded private frame with a timeout, and terminates its own process group on launch failure.
- `WorkerTransport.request(method, params, timeout)`, `next_event(timeout)`, `group_stopped(timeout)` and `shutdown(grace_seconds, terminate_seconds)` provide a bounded writer queue, continuous bounded stdout framing, exact response ID type/value correlation, late-response discard, monotonic request deadlines, independent capped stderr drain and confirmed group stop. A request timeout leaves start acceptance unknown.
- `WorkerLaunchPacket` is the canonical private Pydantic draft type in `contracts/access.py`, registered in `PRIVATE_CONTEXT_MODELS`; its JSON schema is generated. The `context_registry_path` remains the trusted directory namespace, while exact context/job/snapshot JSON and root registrations travel only through the inherited handle. The standalone fixture file checks schema shape; process tests build a fully bound packet from workflow fixtures.
- Worker duplicates protocol stdout before importing runtime components, redirects fd 1 and the Windows StdHandle to stderr, sets CRT binary modes, and serializes all protocol writes. It enforces capabilities before start, validates packet/launch/project/owner/attempt/budget through `GrantRegistry`, and verifies every read entry with `WorkerIOResolver` before `accepted=true`. The fixture handler runs separately from the control reader, emits heartbeat/progress/candidate/completed, and supports blocking/logging/cancel tests.
- Follow-up integration: optional typed `FixtureOutput` binds an attempt staging root, candidate `RunManifest` and one artifact whose hash/size match fixed synthetic bytes. The worker writes and flushes through `NativeRoot.create_file` before candidate/completed events. Without this binding it emits a missing-resource error and no completion. Transport shutdown/fatal errors now stop and join both reader and writer threads after process stop; no queue-waiting writer remains.

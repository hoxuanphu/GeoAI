# Task 1 — SPEC-001 contracts foundation implementation

Date: 2026-11-08. Scope: draft schema foundation only; no GIS/model/solver/native resolver or transport. No Git operation was performed. Roadmap, task tracker and SPEC status are owned by the parent task and were not edited here.

## Implemented

- Added `backend/geoai/contracts/runs.py`: JobSpec, RuntimeProvenance, RunManifest, ResultRevision, EvaluationRecord, MetricsSnapshot and ReportContext. Checks include execution references, CPU/auto/GPU policy shape, matching attempt/job, publication artifacts, fallback reason, GPU device/driver metadata, review metadata/self-parent, numeric finite metrics, business gate reference and official report review snapshot.
- Added `backend/geoai/contracts/rpc.py`: versioned request/success/error/notification envelopes; typed capabilities/start/cancel/shutdown and attempt events; strict IDs/integers/booleans, method/params match, required result even when null, result/error exclusivity, nullable failure ID only for parse/invalid request, domain StructuredError and bounded progress. Success result remains finite JSON for negotiation; an `accepted` payload is validated as a strict acknowledgement.
- Added `backend/geoai/contracts/access.py`: private WorkerBootstrap, WorkerAccessContext, read entries, discriminated managed-local/external-registered-local locations and native file identity metadata. Context checks job/attempt match, unique read references and matching job/snapshot manifest read entries and SHA-256 values. No filesystem I/O is implemented by these models.
- Added explicit public exports and three distinct registries in `contracts/__init__.py`: durable `CONTRACT_MODELS`, public `WIRE_MODELS`, private temporary `PRIVATE_CONTEXT_MODELS`.
- Added offline deterministic `tools/export_contract_schemas.py`; generated `schemas/contracts-v0.1.0.json` directly from Pydantic. Exporter resolves imports/default artifact from its own location and works from another CWD. `--check` detects absent/stale bytes without writing.
- Corrected the GridSpec affine comment to distinguish `[a,b,c,d,e,f]` from GDAL GeoTransform `[c,a,b,f,d,e]`.
- Added `tests/contracts/test_contract_extensions.py` (21 tests) and complete synthetic `rpc-workflow.json` / `worker-access-context.json` fixtures. The existing 30 tests and durable fixture were preserved. The wire fixture contains a complete matching start with context ID/hash; the private fixture includes both location kinds and bootstrap. All paths are synthetic.
- Added bounded implementation notes to `Artchitect/docs/contracts.md` (physical run restriction, runtime/metric/acknowledgement fields) and `worker-resolver.md` (exact private field names and native enforcement boundary). Parent must synchronize surrounding stale implementation-status prose and SPEC/roadmap/tracker.

## Limits and pending work

- No PHY feature-specific parameter/forcing/solver provenance profile has been selected. **RunManifest explicitly rejects any nonempty `physical_model_ids` and any non-null `physical_provenance`, including arbitrary dictionaries.** PhysicalModelSpec and physical/hybrid JobSpec remain valid design records; physical run manifests await typed feature-specific profiles. This is not a claim of physical execution support.
- Pydantic only checks metadata. It does not verify actual bytes/hashes, file identity, Windows path validity/confinement, reparse/ADS/UNC races, rights, owner epoch liveness, attempt revocation, dependency closure against real model manifests, or real device/driver capability. These checks belong to SPEC-009/004 and their native/service tests.
- GPU provenance enforcement recognizes declared `cuda`, `tensorrt`, `onnxruntime_cuda` backends or a supplied device ID. Service runtime registry must validate the actual backend/device; arbitrary backend labels are not evidence of hardware execution.
- JSON Schema does not encode every Pydantic cross-field validator, including method/params correlation, publication/review/gate checks and private context bindings. Consumers still require canonical Pydantic/service semantics.
- All fixture hashes, coverage, metrics and runtime values are synthetic. Existing durable fixture has only one blue asset and cannot drive the six-band ModelSpec. No valid HLS workflow, business model, gate, installer, transport, CRS operation or benchmark was demonstrated. G0/G1 remain open.
- Frozen models are not deeply immutable; immutable publication, authorization and fencing remain coordinator/storage responsibilities.
